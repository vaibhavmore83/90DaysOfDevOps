# Git Branching & Working with GitHub  

1. What is a branch in Git?

Ans: The Branch in a Git helps to work developers in parallel and in isolation without affecting others work.  
  
2. Why do we use branches instead of committing everything to main?

Ans: To make use of parallel development in isolation without affecting others work, we use branches instead of committing everything to main.  

3. What is HEAD in Git?
  
Ans: HEAD is the pointer to the latest changes commit in your branch.  

4. What happens to your files when you switch branches?

Ans: Whenever you switch branches, your current local changes will be overwritten with remote branch changes.  

5. What is the difference between origin and upstream?

Ans: origin and upsteam refers to the remote branches in GitHub.   
  
6. What is the difference between git fetch and git pull?

Ans: git fetch downloads all remote branches under repositories from the Github project; whereas git pull downloads your specific remote branch changes and integrates into your current working branch.  

## Clone vs Fork  

7. What is the difference between clone and fork?

Ans: **clone** downloads the remote repository from Github to your local machines; whereas **fork** creates a copy of the repository into your Github project.  

8. When would you clone vs fork?

Ans: When you want to write to the repository and work directly on it, you need to clone the repository. When you want to work on the repository without affecting original work, you will create a fork. Fork mostly use to contribute to Open Source projects.  
  
9. After forking, how do you keep your fork in sync with the original repo?

Ans: To sync, you need to click on Sync Fork option in your Github UI.
